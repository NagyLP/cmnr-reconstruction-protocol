# Access, Scope and Preservation

## Access classification
- Directly accessible: content successfully retrieved and inspected.
- Indirectly accessible: only surrounding records or metadata are available.
- Inaccessible: content cannot be retrieved through authorized available means.
- Restricted: access requires an additional permission or authorization.
- Unexamined: source has not yet been tested.

Do not collapse indirect access into direct access. A surrounding trace does not grant access to the underlying object or backend.

## Scope dimensions
Define target identity, relevant actors/accounts/devices, application/service, time interval, record types, jurisdiction/context, and explicit exclusions. Keep object, structural, temporal, access and inferential scope separate.

## Preservation
Keep an untouched source copy and work on a duplicate. Record source provenance, acquisition method, tool/version, date/time and timezone, byte size, hash if actually computed, transformations and errors. Do not overwrite original evidence.

## Authorization and privacy
Use only data the analyst is authorized to access. Do not bypass authentication or access controls. Redact credentials, cookies, session tokens, personal data and unrelated records before sharing.
